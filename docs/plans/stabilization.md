## איפה מריצים

**מומלץ במחשב שלך, בדוקר:** רשת אמיתית (Yahoo לא חסום), הנתונים נשמרים בין ימים, ורואים את הדשבורד.

```bash
docker compose up -d --build          # db → migrate → api + worker → frontend
```

**שתי אפשרויות לריצה היומית:**
- **א. אוטומטית (עדיף, כי בודק גם את המתזמן):** ב-`.env` להגדיר `SCHEDULER_ENABLED=true`, ולהשאיר את ברירות המחדל: `PIPELINE_SCHEDULE="30 18 * * mon-fri"` (18:30 ניו יורק, 01:30 שעון ישראל). המחשב צריך להיות דלוק בשעה הזו.
- **ב. ידנית:** אחרי סגירת המסחר (מ-23:00 שעון ישראל), `sh infra/deploy/verify.sh`. היא מריצה את כל הסוכנים על ה-watchlist ומפיקה דוח.

**מה מוגדר כבר:**
- **9 המניות** נקראות מטבלת ה-watchlist במסד הנתונים, לא מ-`WATCHLIST` ב-`.env`.
- **retry:** ריצת סוכן שנכשלה מנוסה שוב באותו יום (`PIPELINE_RETRY_*`).
- **מכסות:** `LLM_QUOTA_MAX_WAIT_SECONDS=60` (חשוב למכסות הדקה של המודלים החינמיים).

## הבדיקה היומית (כ-5 דקות)

```bash
# 1. הדוח של היום. אם המתזמן כבר הריץ, הפקודה רק קוראת את התוצאות השמורות.
#    הקובץ נכתב בתוך הקונטיינר, ואז מועתק לריפו.
sh infra/deploy/verify.sh --json /tmp/verify.json
docker compose cp api:/tmp/verify.json docs/evaluation/verify-$(date +%F).json

# 2. המתזמן והג'ובים
curl -s localhost:8000/health

# 3. עלות וספקים
docker compose exec api python -m scripts.token_report --days 1 --by provider

# 4. רק אם verify הראה WARN או FAIL: איפה בדיוק
docker compose exec api python -m scripts.agent_card <agent> --days 7
```

**מה רושמים ביומן למטה:** תאריך, PASS / WARN / FAIL, ריצות שהושלמו מתוך הכלל, fallbacks, קריאות FMP, עלות, ומה הוסבר או תוקן.

## מה עושים כשמשהו נכשל

| מה רואים | מה זה כנראה | מה עושים |
|---|---|---|
| `FAIL`: ריצת סוכן נכשלה | באג, או ספק שנפל | השגיאה מופיעה ב-`agent_card <agent>` (בשורה "failed run"). באג → issue או תיקון. ספק → לבדוק אם ה-retry השלים |
| `WARN` עם fallbacks | Gemini 503 או מכסה מלאה | `token_report --by provider`: האם Groq השלים? אם כל השרשרת נפלה, להוסיף `CEREBRAS_API_KEY` או להעלות את `LLM_QUOTA_MAX_WAIT_SECONDS` |
| `WARN` עם נתונים חסרים | צפוי בחלק מהמקרים (institutional בתוכנית החינמית, XOM בלי 10-K) | לוודא שזה ברשימת ה"מוסבר" בסעיף 3 של FUTURE. אם זה חדש, לרשום שם |
| `/health`: `missed` | המחשב היה כבוי בשעת הריצה | לא באג, אבל היום לא נספר. מריצים ידנית ומשאירים את המחשב דלוק |
| FMP קרוב ל-250 | שינוי ב-watchlist, או `--force` חוזר | לבדוק ב-`verify` כמה קריאות לכל מניה. הצפי הוא כ-12 בריצה מלאה, ופחות כשהנתונים לא השתנו |

**כלל:** תיקון בזמן הייצוב רק לבאג או לתקלת נתונים. לא משנים פרומטים, משקלות או מודלים. תיקון כזה מאפס את ספירת הימים.
